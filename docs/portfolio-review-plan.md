# 포트폴리오 검토 및 개정 실행 계획

검토일: 2026-09-08 · 대상: 현재 로컬 구현

2026-09-09 반영: 제공된 ResearchQ 실제 캡처와 Sepsis 보고서 도표를 연결하고 `/research/sepsis` 독립 상세를 추가했다. 모델별 ROC-AUC 전사, 공동 기여, 실험 불일치와 원본 공개 보류를 표시했다. Blog 본문/영구 URL은 아직 미확인이다. [미디어 출처 기록](media-provenance.md) 참조.

## 후속 구현 기록 — 2026-09-08

아래 최초 평가는 변경 전 스냅샷이다. 이후 다음 구현을 진행했다.

- 세 프로젝트를 `ProjectDetail` 공통 템플릿과 `src/data/projects.js` 데이터로 분리. 문제·본인 기여·접근 방식·결과/규모·근거 상태·한계·관련 자료를 같은 구조로 표시한다.
- 기존 수치를 새로 검증한 것처럼 표시하지 않고 reported 값과 측정 조건의 공백을 명시했다. 데이터 규모를 성능으로 표현하지 않는다.
- Research는 `/sepsis?context=research`로 같은 연구 프로젝트를 열되 Research 선택 상태와 연구 프로젝트 안내를 유지한다. 독립 논문이나 새 리포트를 만들지 않았다.
- 관련 항목 관계를 공통 데이터로 옮기고 Blog↔프로젝트, 관련 경력↔작업을 연결했다. ResearchQ·Sepsis의 역할 링크에서 이력서에 접근할 수 있다. Experience 포스트/메뉴와 헤더 Résumé는 복원하지 않았다.
- 페이지별 브라우저 제목·설명, 예고 글의 클라이언트 렌더링 noindex, 없는 경로 안내, 본문 바로가기와 상세 전환 초점 처리를 추가했다. 서버 렌더링 SEO·전체 접근성 인증은 아직 아니다.
- 콘텐츠 분류·경로 문맥·관련 항목·초안 상태에 대한 5개 자동 테스트를 추가했다.

남은 우선 과제: 실제 산출물 링크, 성과 원자료, 공개 가능한 화면, 완성된 글과 연구 문서 확보. 이번 구조 개선만으로 원래의 콘텐츠 검증 문제까지 완료된 것은 아니다.

## 결론

콘텐츠를 탐색하는 틀은 갖췄지만, 결과와 근거를 확인할 수 있는 공개용 포트폴리오는 아직 미완성이다. 다음 작업은 새 레이아웃 제작이 아니라 공개 콘텐츠 확정 → 근거 정리 → 상세 콘텐츠 보강 순서다.

개정한 17개 기준 중 **완료 5 / 부분 충족 9 / 미충족 3**이다. 항목 수 기준이며, 전체 완성도 백분율은 아니다. 특히 성과 검증과 실제 산출물 링크는 다른 UI 기능으로 대체할 수 없는 공개 조건이다.

이번 작업은 검토와 실행 계획 작성이다. 기존 화면·콘텐츠·배포 설정은 변경하지 않았다.

## 1. 유지할 디자인 원칙

- 큰 Hero, 희망 직무 카드, JP 마크, Contact footer, Let’s talk를 다시 만들지 않는다.
- 고정 헤더의 Jongho Park / Data Scientist와 GitHub·LinkedIn을 유지한다. 직함을 더 크게 강조하지 않는다.
- All / Projects / Research / Blog와 고정 내비게이션·툴바를 유지한다.
- 리스트·이미지 그리드를 지원하며, 클릭하면 같은 헤더·사이드바 안의 상세로 바로 이동한다. 미리보기 단계를 추가하지 않는다.
- 경력은 포스트 및 컬렉션에서 제외하고 이력서에 둔다. 단, 이력서를 발견할 수 있는 문맥상 링크가 필요하다.
- 장식보다 실제 결과물과 설명을 우선한다. 글래스 효과는 배경 수준, 애니메이션은 짧고 선택적으로 유지한다.
- 화면상 프로젝트 이동 문구는 Go를 유지한다. Research는 출판물이 확정되기 전까지 Publications로 바꾸지 않는다.

## 5. 개선 실행 순서

### P0 — 콘텐츠 확정과 검증: 다음 작업

1. 대표 프로젝트 세 후보를 공개 목록으로 확정한다. 각 항목의 업무/사이드/연구 구분과 본인 기여를 기록한다.
2. 위 검증 대장에 실제 자료를 연결한다. 수치는 근거 확인 전 확정 카피로 취급하지 않는다.
3. 연구 리포트 존재 여부와 Blog 세 편의 작성 상태를 확정한다. 없는 문서를 보충해서 만든 것처럼 보이지 않게 한다.
4. 공개용 자산 목록을 만든다: 스크린샷, 평가 그래프, 코드, 데모, PDF, 사용 권한, 비식별 처리 여부.

완료 조건: 공개 항목마다 제목·분류·역할·요약·상태·실제 목적지·주장 근거가 정리되고, 초안과 공개 완료가 분리됨. 자료 없는 항목은 보류 상태로 명시.

### P1 — 현재 레이아웃 안에서 콘텐츠 깊이와 이동 동선 보강

- 공통 상세 컴포넌트와 콘텐츠 데이터를 분리한다. 공통 필드는 문제 → 본인 역할 → 핵심 선택/대안 → 결과·평가 → 한계 → 관련 자료로 통일한다.
- 홈 프로젝트 카드에는 긴 스택 나열 대신 검증된 결과 한 줄을 넣는다. 수치가 없으면 확인 가능한 산출물을 설명한다.
- 독립 리포트가 확보되면 별도 Research 상세를 만들고 Research 선택 상태를 유지한다. 자료가 없으면 중복 카드를 억지로 유지하지 않는다.
- 실제 Blog 본문 템플릿에 날짜·요약·본문·그림 설명·참고자료를 둔다. 빈 글을 늘리지 않는다.
- 관련 콘텐츠 ID를 데이터로 관리해 프로젝트 ↔ 연구 ↔ 글을 양방향 연결한다. 실제 관련성이 있는 항목만 연결한다.
- 이력서는 헤더 Résumé나 Experience 컬렉션을 복원하지 않고 프로젝트의 역할/경력 문맥에서 연결한다. 루트 PDF는 최신 내용·공개 여부를 확인한 뒤 배포 자산으로 연결한다.
- 상세에서 돌아갈 때 이전 컬렉션·검색·보기 상태를 유지한다. 직접 URL로 진입해도 분류가 맞도록 한다.

완료 조건: 공개 카드는 실제 내용으로 이동하고, 관련 근거를 한 번의 추가 클릭으로 확인 가능. Research 선택 오류와 이력서 발견 문제 해결. 공통 셸 유지.

### P2 — 실제 미디어와 공개 품질

- 현재 SVG 도식은 보조 설명으로 유지 가능하다. 우선 확보된 실제 스크린샷·평가 그래프로 대표 커버와 상세 갤러리를 보강한다. 재구성·합성 화면은 계속 구분한다.
- 갤러리는 설명·출처·대체 텍스트·확대·키보드 조작을 제공한다. 자동 재생이나 무한 애니메이션은 추가하지 않는다.
- 태그 필터는 확정 콘텐츠에 실질적인 교차 탐색 필요가 있을 때 추가한다. 7개 후보를 위해 과도한 필터 UI를 만들지 않는다.
- 홈·각 상세의 title/description, 실제 배포 주소 기반 canonical/OG, 사실에 맞는 구조화 데이터를 마련한다. 초안은 검색 노출 대상에서 제외한다.
- 없는 경로의 안내, 직접 상세 URL 새로고침, 배포 base 경로, 실제 파일 링크를 테스트한다.
- 본문 바로가기, 상세 전환 후 초점, 고정 영역에 가려지지 않는 키보드 초점, 색 대비·확대·터치 영역을 검증한다. Go의 시각 문구는 유지하되 접근 가능한 이름에 프로젝트 맥락을 포함한다.
- 사용하지 않는 기존 화면/CSS와 중복 콘텐츠 데이터를 정리하고 경로별 로딩을 검토한다. 미디어 크기를 예약하고 화면 밖 자산을 지연 로드한다. 저사양·모바일 환경에서 성능을 실제 측정한다.

완료 조건: 빌드/린트와 라우트·링크·키보드·모바일 회귀 검증 통과. 실제 미디어가 근거를 설명하며, 모션 감소 설정에서 움직임 없이 정보 전달. 성능은 번들 크기만으로 판정하지 않음.

### P3 — 공개 후 학습

- 우선 30초 사용자 검증을 진행하고, 자주 못 찾는 결과·근거의 위치를 조정한다.
- 분석 도입을 결정한 경우에만 상세 열기·산출물 링크 클릭·관련 글 이동을 최소 이벤트로 측정한다. 개인 식별 정보와 검색 원문은 수집하지 않는 방향으로 설계한다.
- 클릭이 적다는 이유만으로 장식/CTA를 늘리지 않는다. 콘텐츠의 관련성·이름·근거 접근성부터 검토한다.

## 6. 이번 검증의 범위와 증거

- 실제 브라우저: All 7개, Research→Sepsis로 이동하면서 Projects가 활성화되는 현상, Blog의 본문 미작성 안내를 확인했다.
- 모바일 390×844: 문서 너비 390, 그리드 1열. 헤더/내비게이션/툴바 top은 0/58/118px이며 600px 스크롤 후에도 동일했다.
- `npm run build`, `npm run lint` 통과. 산출물 JS 289.23kB(gzip 87.48kB), CSS 57.88kB(gzip 11.92kB). 이는 로딩 성능 실측 결과가 아니다.
- 실제 외부 계정 소유권, 저장소·서비스 가용성, PDF 내용 일치, 모든 화면 크기·보조기기, 실제 방문 분석, 성과 수치의 원자료는 검증하지 않았다.

- `src/pages/PortfolioExplorer.css`: 고정 영역·모바일 전환·초점 스타일
- `src/pages/ResearchQPost.jsx`, `SepsisPost.jsx`, `VationoPost.jsx`: 현재 상세 구조와 성과 주장

- `src/App.jsx`, `index.html`: 현재 경로 구성·기본 메타데이터
